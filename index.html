How it works

01
Event ingestion
Your API sends a POST /ingest on every rejected login. The Worker validates the payload, writes the failure to D1, and returns 202 immediately to keep ingestion latency under 5 ms.
02
Async enrichment
In waitUntil, the Worker resolves geo coordinates (Zippopotam + U.S. Census fallback, cached in KV), assigns an anomaly score (0–100), checks the IP against Spamhaus DROP and CINS Army threat feeds, and evaluates active alert rules.
03
Live streaming to the dashboard
The dashboard holds an open Server-Sent Events connection. New events appear within seconds. KV-backed dedup prevents duplicate delivery on reconnect. The dashboard updates all seven views — map, log, stats, intel — without a page refresh.
04
Investigate & respond
Probe any IP for AbuseIPDB reputation data directly from the log view. Block a single IP or an entire country with optional expiry — the rule is written to D1 and the KV fast-path cache. Blocked IPs are rejected by Hono middleware before reaching any route handler.
05
Analyze patterns
The Stats view surfaces an attack heatmap (day-of-week × hour grid), time-series chart, per-route breakdown, and failure reason distribution. The Intel view delivers an automated threat analysis report cached for five minutes.

Features

Anomaly scoring engine
Every event receives a 0–100 score and pattern classification: brute_force, credential_stuffing, rate_probe, tor_exit, known_bad_ip, bot, geo_concentration.
Three map modes
Switch between a command canvas with animated attack arcs, a Leaflet interactive tile map, and a Cobe WebGL 3D globe — without leaving the view.
IP deep probe
One-click AbuseIPDB enrichment with confidence score, abuse categories, reverse-lookup hostname, and ISP. API key never leaves the Worker.
Edge-enforced blocking
IP and country blocks written in the dashboard are enforced by Hono middleware on every Worker request. Sub-millisecond enforcement via Workers KV fast path.
Alert rules
CRUD interface for threshold-based alert rules. Brute-force (N failures/T seconds) and anomaly score triggers. Cooldown prevents alert storms from the same source.
Threat feed correlation
Ingested IPs checked against Spamhaus DROP and CINS Army known-bad lists. Matches flagged inline — no separate scan required.
Share tokens
Generate a time-limited public link showing aggregate stats (event count, top countries, top routes). Raw IPs and individual events are never exposed.
Export & backfill
CSV or JSON export (up to 10,000 rows). Geo backfill endpoint resolves coordinates for historic events ingested without location data.

Engineering Decisions

Edge-native — no separate server layer
Every operation (ingestion, SSE streaming, block enforcement, geo lookup) runs inside a Cloudflare Worker. No Node.js server, no external database host, no proxy layer to maintain. Cold starts are structurally impossible on Cloudflare's edge network.
SSE over WebSockets
Auth-failure data flows in one direction (server → browser). SSE uses standard HTTP/2 multiplexing, requires no special protocol negotiation, and avoids the Durable Objects requirement that full-duplex WebSocket connections impose on CF Workers. Reconnect behavior is handled automatically by the browser.
waitUntil-deferred enrichment
Geo resolution, anomaly scoring, alert evaluation, and KV cache writes all run in waitUntil. The POST /ingest endpoint returns 202 immediately — enrichment completes asynchronously within the same Worker invocation without adding latency to the write path.
Block enforcement as middleware
IP and geo blocks are enforced by a Hono middleware reading from a Workers KV fast-path cache (D1 fallback on miss). No external firewall, no WAF rule propagation delay. A blocked IP is rejected before it reaches any route handler on every Worker request.
Anomaly scoring at ingestion time
Scoring runs inline on write (or in waitUntil for slower heuristics). Every event in D1 already carries its score and pattern classification. The dashboard never computes scores on the read path — queries are simple column reads.

Security Architecture

Admin auth
All admin endpoints require a pre-shared bearer token validated via Web Crypto timingSafeEqual. No tokens are evaluated by string comparison.
Block enforcement
Blocking middleware sits at the first Hono layer. Blocked IPs and country codes are rejected before reaching any route handler. KV cache keeps enforcement under 1 ms.
Share token scoping
Public share tokens expose aggregate statistics only. Raw IPs and individual event records are never returned on share token responses.
API key proxying
AbuseIPDB enrichment calls are proxied through the Worker. The API key is a Worker secret — it is never sent to the browser or exposed in any client response.
CSRF protection
CSRF tokens required on all state-mutating endpoints (POST, PUT, DELETE). Token validated server-side on every write path.
KV dedup hardening
SSE dedup keys use a salted hash of the event ID, not the raw IP, to prevent KV namespace enumeration. Alert cooldown prevents alert storms from repeated events.
